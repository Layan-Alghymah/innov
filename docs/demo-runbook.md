# دليل تشغيل العرض التجريبي

هذه النسخة **Demo MVP / Early Operational Preview** وليست إصدار إنتاج أو تقييمًا رسميًا من هيئة الحكومة الرقمية.
جميع قيم الجاهزية المعروضة تحمل وصف **مؤشر جاهزية تقديري داخلي** وتحسب من محرك الامتثال الحالي.

## 1. المتطلبات

- Node.js 20 أو أحدث.
- PostgreSQL متاح محليًا أو عبر اتصال مخصص للعرض.
- قاعدة بيانات عرض منفصلة ونظيفة موصى بها. لا تستخدم قاعدة بيانات الاختبارات للعرض؛ الاختبارات تنشئ سجلات كثيرة عمدًا.

أنشئ `.env` محليًا:

```env
DATABASE_URL="postgresql://user:password@localhost:5432/innovation_demo?schema=public"
AUTH_SECRET="replace-with-a-long-random-demo-secret"
AUTH_TRUST_HOST="true"
STORAGE_DRIVER="memory"
```

`AUTH_TRUST_HOST=true` مطلوب عند تشغيل `next start` محليًا. في الاستضافة الذاتية
يجب تفعيله فقط بعد ضبط الوكيل العكسي أو موازن الحمل للتحقق من ترويسة `Host`.

`STORAGE_DRIVER=memory` مناسب لجلسة عرض محلية واحدة فقط. الملفات المرفوعة تبقى ما دام خادم التطوير نفسه يعمل، وتفقد بعد إعادة تشغيله.

لاستمرار الملفات بين عمليات التشغيل، استخدم S3 أو MinIO:

```env
STORAGE_DRIVER="s3"
S3_BUCKET="innovation-evidence-demo"
S3_REGION="auto"
S3_ENDPOINT="http://localhost:9000"
S3_ACCESS_KEY_ID="local-demo-access-key"
S3_SECRET_ACCESS_KEY="local-demo-secret-key"
S3_FORCE_PATH_STYLE="true"
```

لا تُحفظ قيم حقيقية أو أسرار مشتركة في Git.

## 2. التهيئة والتشغيل

```powershell
npm install
npm run db:deploy
npm run db:seed
npm run dev
```

الرابط الافتراضي:

```text
http://localhost:3000
```

إذا كان المنفذ مستخدمًا:

```powershell
npm run dev -- -p 3001
```

## 3. حسابات العرض المحلية

هذه الحسابات للاستخدام المحلي أو العرض فقط:

| الدور | البريد | كلمة المرور |
|---|---|---|
| مدير النظام | `admin@innovation.local` | `Admin@12345` |
| محرر داخلي | `editor@innovation.local` | `Demo@12345` |
| شريك خارجي | `partner@innovation.local` | `Demo@12345` |
| مطّلع | `viewer@innovation.local` | `Demo@12345` |

يمكن تغيير كلمات المرور قبل البذر:

```env
SEED_ADMIN_EMAIL="admin@innovation.local"
SEED_ADMIN_PASSWORD="choose-a-demo-password"
SEED_DEMO_PASSWORD="choose-another-demo-password"
```

إعادة تشغيل البذرة آمن ومتكرر التنفيذ ولا يكرر السجلات أو يحذف البيانات. كما لا يمحو قرارات مراجعة الأدلة والاقتراحات التي تمت أثناء العرض. للعودة إلى حالة العرض الأولية استخدم قاعدة Demo جديدة ونظيفة ثم نفّذ الهجرة والبذرة.

## 4. رحلة العرض المقترحة

1. سجل الدخول بحساب مدير النظام.
2. افتح لوحة التحكم وتحقق من ظهور `مؤشر جاهزية تقديري داخلي`.
3. افتح ملف الامتثال ثم حل `منصة الصيانة الاستباقية للأصول`.
4. استعرض الحقول والأدلة الناقصة والروابط إلى بيانات الحل وأدلته.
5. افتح دليل `تقرير قياس أثر التجربة - بانتظار المراجعة`.
6. راجع اقتراح التصنيف واقتراح الربط بالمتطلب؛ اقبل أو ارفض كل اقتراح بشريًا.
7. قدّم الدليل للمراجعة، ثم ابدأ المراجعة واعتمده بحساب المدير.
8. ارجع إلى ملف الامتثال وتحقق من تغير الجاهزية وبقاء الفجوات غير المستوفاة.
9. استخدم زر الطباعة أو تصدير CSV.

لإظهار الاستخراج من ملف حقيقي، ارفع PDF أو DOCX أو XLSX منظمًا عبر صفحة أدلة الحل، ثم شغّل التحليل من صفحة الدليل. نجاح الاستخراج لا يعتمد الدليل تلقائيًا.

## 5. بيانات العرض

البذرة تنشئ:

- مدير نظام ومحررًا داخليًا معتمدًا.
- إدارة التحول الرقمي وهدفًا استراتيجيًا ونشاطًا وفكرة مرتبطة.
- حل `منصة الصيانة الاستباقية للأصول`.
- المتطلبات القابلة للتهيئة `5.23.1` إلى `5.24.2`.
- دليل اعتماد معتمد يحتسب في الجاهزية.
- فجوة دليل أثر وفجوة حقل مستفيدين.
- نتيجة تحليل مكتملة باقتراحين معلقين للمراجعة البشرية.

## 6. حدود العرض

- الوحدات المستقبلية غير المكتملة مخفية من التنقل الرئيسي، ولم تُحذف نماذجها أو وثائقها.
- لا يوجد تصدير ZIP متقدم؛ المتاح طباعة وCSV أساسي.
- التحليل الافتراضي محلي وقائم على قواعد، وليس قرارًا آليًا.
- التخزين الذاكري غير مناسب للإنتاج أو لإعادة تشغيل الخادم.
- يجب استخدام قاعدة عرض منفصلة للحصول على سجل حلول نظيف.
